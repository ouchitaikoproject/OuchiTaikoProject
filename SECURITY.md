# Security Policy

## Supported Versions

| Version | Supported          |
| ------- | ------------------ |
| 1.0.x   | :white_check_mark: |
| < 1.0   | :x:                |

## Reporting a Vulnerability

The OuchiTaiko Project takes security seriously. While this is primarily a hardware project, there may be firmware or software vulnerabilities.

### What qualifies as a security issue?
- Firmware bugs that could damage hardware
- Code that could brick the RP2040 controller
- Issues that could cause physical harm during operation
- Data privacy concerns

### How to report
1. **DO NOT** open a public GitHub issue for security vulnerabilities
2. Contact via GitHub Security Advisories (preferred)
3. Or email details through the GitHub Issues system with "SECURITY" in the title

### What to include
- Description of the vulnerability
- Steps to reproduce
- Potential impact
- Suggested fix (if available)

### Response timeline
- **24 hours**: Initial acknowledgment
- **7 days**: Assessment and triage
- **30 days**: Fix developed and tested (if applicable)

### Disclosure policy
- Security issues will be disclosed after a fix is available
- Credit will be given to reporters (unless anonymity is requested)

## Safe Building Practices

This project involves:
- Soldering (burn hazard)
- Power tools (injury hazard)
- Electrical components (shock hazard)

Always follow proper safety procedures when building hardware projects.
